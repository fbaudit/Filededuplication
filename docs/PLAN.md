# FileDedup 개발 계획서

**Windows 중복 파일 제거 + 초고속 파일 검색 프로그램**

- 대상 조직: 디지털포렌식팀 (내부 배포용)
- 저장소: `fbaudit/Filededuplication`
- 작성일: 2026-07-17

---

## 1. 개요 및 목표

Windows 환경에서 특정 폴더(하위 폴더 포함)를 스캔하여 중복 파일을 찾아 안전하게 제거하고, 아울러 Everything 수준의 초고속 파일명 검색과 파일 내용 기반 전문(全文) 검색을 제공하는 데스크톱 프로그램을 개발한다.

| 기능 영역 | 벤치마킹 대상 | 목표 |
|---|---|---|
| 중복 파일 검사/제거 | **DoubleKiller** | 다중 기준(해시·이름·크기·날짜) 조합 검사, 자동 선택 규칙, 안전 삭제 |
| 초고속 파일명 검색 | **Everything** | NTFS MFT 직접 읽기로 볼륨 전체를 수 초 내 인덱싱, 타이핑 즉시 검색 |
| 내용 기반 검색 | (Windows Search 대체) | 문서 텍스트 추출 → 전문 검색 인덱스, 한국어 부분일치 지원 |

포렌식 팀 업무 특성을 반영해 **모든 삭제 작업 전 해시값이 포함된 CSV 보고서**를 남길 수 있게 하고, 기본 삭제 방식은 휴지통 이동으로 하여 실수로 인한 데이터 유실을 방지한다.

## 2. 벤치마킹 분석

### 2.1 DoubleKiller (중복 검사)
채택할 핵심 개념:
- **기준 체크박스 조합**: 파일명 / 크기 / 만든 날짜 / 수정 날짜 / 체크섬(CRC32) 중 원하는 기준을 골라 조합하고, 선택된 기준을 **모두** 만족하는 파일들을 중복 그룹으로 묶는 방식. 본 프로그램은 여기에 MD5, SHA-256을 추가한다.
- **그룹 단위 결과 리스트**: 중복 그룹별로 파일을 나란히 보여주고 체크박스로 삭제 대상을 표시.
- **선택 마법사(selection wizard)**: "각 그룹에서 최신 파일만 남기기", "특정 폴더의 파일 우선 보존" 같은 규칙으로 수천 개 파일을 일괄 선택. 그룹당 최소 1개는 반드시 보존되도록 보호.
- 제외 패턴(마스크), 최소/최대 크기 필터.

### 2.2 Everything (파일명 검색)
채택할 핵심 개념:
- **NTFS MFT(마스터 파일 테이블) 직접 열거**: 디렉터리 재귀 탐색 대신 `FSCTL_ENUM_USN_DATA`로 볼륨의 전체 파일 레코드를 한 번에 읽어 수 초 만에 인덱스 구축 (관리자 권한 필요).
- **USN 체인지 저널 모니터링**: 파일 생성/삭제/이름변경을 실시간 반영.
- **메모리 상주 인덱스 + as-you-type 검색**: 파일명(소문자화) 배열과 부모 디렉터리 참조 체인만 메모리에 유지, 전체 경로는 표시 시점에 지연 조립. 키 입력마다 즉시 부분 문자열 매칭.
- **검색 문법**: 공백=AND, `*.pdf` 와일드카드, `path:` 필터 등 기본 문법 지원.
- 관리자 권한이 없거나 NTFS가 아닌 경우: 사용자가 지정한 폴더를 SQLite 인덱스에 저장하는 **폴더 인덱스 모드**로 자동 폴백.

## 3. 기능 요구사항

### 3.1 중복 파일 검사/제거
1. 폴더 선택(복수 가능, 하위 폴더 포함/제외 옵션) 후 전체 스캔.
2. 중복 판별 기준(조합 가능): **파일명**(대소문자 무시 옵션), **파일 크기**, **만든 날짜**, **수정 날짜**, **CRC32**, **MD5**, **SHA-256**.
3. 성능 최적화 3단계 파이프라인: 크기 그룹핑 → 선두 64KB 부분해시 → 전체 해시. 같은 크기의 후보끼리만 해시를 계산해 대용량 폴더에서도 빠르게 동작.
4. 결과는 중복 그룹 리스트로 표시(경로, 크기, 날짜, 해시). 자동 선택 규칙: 최신/최구(最舊) 보존, 폴더 우선 보존, 짧은 경로 보존, 패턴 선택.
5. 처리 방식: **휴지통 이동(기본)** / 영구 삭제(확인 필수) / 지정 폴더로 이동.
6. 처리 전 CSV 보고서(전체 경로, 크기, 생성·수정일, CRC32/MD5/SHA-256, 그룹 ID, 처리 결과) 저장 옵션.
7. 필터: 제외 패턴(글롭), 최소/최대 파일 크기, 숨김/시스템 파일 제외 옵션.

### 3.2 초고속 파일명 검색
1. MFT 모드: 관리자 권한 + NTFS 볼륨에서 전체 드라이브 인덱싱(수 초), USN 저널로 증분 갱신.
2. 폴더 인덱스 모드: 지정 폴더를 SQLite 인덱스에 저장(비관리자 폴백).
3. 타이핑 즉시 결과 갱신, 결과 수십만 건 가상화 그리드, 정렬, 탐색기에서 열기.

### 3.3 내용 기반 검색
1. 인덱싱 대상 폴더·확장자 지정, 백그라운드 인덱싱, 크기+수정일 기반 증분 갱신.
2. 지원 형식: 텍스트 계열(txt/log/csv/md/소스코드, UTF-8·CP949 인코딩 감지), Office(docx/xlsx/pptx), PDF(텍스트 레이어), HWP 5.0/HWPX(본문 텍스트).
3. SQLite FTS5 전문 검색 + trigram 보조 인덱스로 한국어 부분일치 지원. 결과에 매칭 스니펫 표시.

### 3.4 공통/UI
- 탭 구성: ① 중복 검사 ② 파일명 검색 ③ 내용 검색 ④ 설정.
- 프로그램 아이콘: 클로드 스타일의 주황색 스타버스트 아이콘을 자체 제작(공식 로고 원본은 상표 자산이므로 복제하지 않음).
- 한국어 UI 기본.

## 4. 기술 스택

| 항목 | 선택 | 근거 |
|---|---|---|
| 언어/런타임 | C# / .NET 8 (LTS) | 대용량 I/O·병렬 해시 성능, P/Invoke로 Windows 네이티브 API 접근, 단일 exe 배포 |
| UI | Avalonia UI 11 (MVVM) | XAML 기반 현대적 UI, Linux CI에서도 빌드·테스트 가능, `dotnet publish -r win-x64`로 Windows 단일 실행파일 생성 |
| 인덱스/DB | SQLite + FTS5 (Microsoft.Data.Sqlite) | 무설치 단일 파일 DB, 파일명 인덱스와 전문검색 모두 커버 |
| 해시 | System.Security.Cryptography (MD5/SHA-256), System.IO.Hashing (CRC32) | 표준 구현으로 포렌식 신뢰성 확보 |
| 문서 추출 | DocumentFormat.OpenXml(Office), PdfPig(PDF), 자체 경량 파서(HWP 5.0: OLE Compound+zlib / HWPX: zip+XML) | HWP는 국내 포렌식 업무 필수 형식 |
| MFT/USN | P/Invoke: `CreateFile`, `DeviceIoControl`(`FSCTL_ENUM_USN_DATA`, `FSCTL_READ_USN_JOURNAL`) | Everything과 동일 원리 |
| 빌드/배포 | GitHub Actions (windows-latest) → self-contained 단일 exe 아티팩트 | 팀 배포 간편화 |

## 5. 아키텍처 및 프로젝트 구조

```
Filededuplication/
├── docs/PLAN.md                      # 본 계획서
├── FileDedup.sln
├── src/
│   ├── FileDedup.Core/               # 순수 로직 (플랫폼 독립, 유닛테스트 대상)
│   │   ├── Scanning/                 # 폴더 재귀 스캔 (병렬, long-path 지원)
│   │   ├── Hashing/                  # CRC32/MD5/SHA256 + 부분해시 파이프라인
│   │   ├── Dedup/                    # 중복 판별 엔진, 자동선택 규칙
│   │   ├── Index/                    # SQLite 파일명 인덱스 + FTS5 콘텐츠 인덱스
│   │   ├── Extract/                  # 텍스트 추출기 (txt/office/pdf/hwp/hwpx)
│   │   └── Delete/                   # 삭제 실행(휴지통/영구/이동) + CSV 보고서
│   ├── FileDedup.Windows/            # Windows 전용: MFT/USN 리더, 휴지통 P/Invoke
│   └── FileDedup.App/                # Avalonia GUI (MVVM)
├── tests/FileDedup.Core.Tests/       # xunit 유닛/통합 테스트
├── assets/                           # icon.svg, icon.ico
└── .github/workflows/build.yml       # Windows exe 빌드 파이프라인
```

설계 원칙:
- **Core는 플랫폼 독립**: 스캔·해시·판별·인덱싱 로직은 어떤 OS에서도 테스트 가능하게 유지.
- **Windows 전용 기능은 인터페이스로 분리**: `IVolumeIndexer`(MFT), `IRecycleBin`(휴지통) 인터페이스를 Core에 두고 Windows 구현체를 주입. 비Windows/비관리자 환경에서는 폴백 구현 사용.
- **UI는 뷰모델만 Core에 의존** (MVVM).

## 7. 검증 계획

- **유닛테스트** (`dotnet test`): 기준 조합별 중복 판별, 부분해시 파이프라인 정확성(같은 크기·다른 내용 구분), 자동선택 규칙(그룹당 1개 보존 보장), 문서 텍스트 추출, FTS5 인덱싱/검색.
- **통합테스트**: 임시 디렉터리에 중복 파일 세트를 생성해 스캔 → 판별 → 이동/삭제 → CSV 보고서까지 전체 흐름 검증.
- **빌드 검증**: `dotnet publish -c Release -r win-x64 --self-contained` 성공 및 단일 exe 생성 확인.
- **Windows 전용 기능**(MFT/USN, 휴지통): 인터페이스 분리 + 모의(mock) 테스트로 로직 검증. 실환경 수동 테스트 체크리스트를 README에 포함(관리자 권한 실행, NTFS 볼륨 인덱싱 시간, USN 갱신 반영 확인).

## 8. 리스크 및 대응

| 리스크 | 대응 |
|---|---|
| MFT 읽기는 관리자 권한 필요 | 권한 없으면 폴더 인덱스 모드로 자동 폴백, UI에 모드 표시 |
| HWP 포맷 파싱 복잡도 | 본문 텍스트 추출만 목표로 경량 파서 구현, 실패 시 해당 파일만 건너뛰고 로그 |
| 대용량 볼륨 해시 시간 | 3단계 파이프라인으로 전체 해시 대상 최소화, 병렬 처리, 진행률·취소 지원 |
| 잘못된 삭제로 인한 자료 유실 | 기본 휴지통 이동, 그룹당 1개 보존 강제, 삭제 전 CSV 보고서 |
| 상표(로고) 문제 | 클로드 공식 로고를 복제하지 않고 유사 스타일 아이콘 자체 제작 |
